## 决策与替代方案

固定官方 Python 基础镜像 digest，不改全局镜像配置。服务器官方 Registry 请求超时后，将官方 manifest/config 与已有四个公共层逐一按摘要核对并恢复完整镜像；恢复后 ID、RootFS 与官方原件全等，没有使用任意镜像重打标签。默认软件包源经用户允许，最终使用标准 Dockerfile 的 APT/PyPI 默认值和哈希锁文件。官方软件源超时与缓存环境试跑单独保留，最终两轮的镜像、源码、日志不混写。

保留全局缓存键和保守刷新策略。指令及文件集合、配方、CFLAGS 或编译器改变时刷新两个对象；只改声明则复用实际图并重算发现。逐目标影响闭包优化超出个人实验边界，不为缓存命中率牺牲配置身份。

个人用例选择条件 include 和宏开关，补足已有 -O0→-O1 用例不改变实际边集的缺口。先写固定边集和发现预期，再对照同提交全量结果；正常用例覆盖宏启用与撤销，内存变异只证明错误复用能被检出，不把两个子场景失败当成独立变异证明。
