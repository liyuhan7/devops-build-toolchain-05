## 背景与约束

在既有教学实现上完成 E8 真实 BuildChecker 基线、E9 C0—C3 与个人独立测试。限定两个翻译单元、根目录头文件、显式规则与简单变量；只支持三种既定 CFLAGS。用户要求镜像直连官方；既有共享代码与其他成员材料保持原样。

## 选择与替代方案

历史实际图采用 BuildChecker full_check 的真实 strace 图并与 GCC 对象投影双向核对，保留 trace_id、进程树和原始日志。相较只保存 GCC 静态投影，这一选择可以追溯观察来源，但需要允许容器跟踪系统调用。

沿用全局配置键与保守刷新两个对象的策略。预处理指令及文件集合、配方、编译参数或 GCC 版本变化就刷新；普通表达式变化可复用；只改依赖声明时复用实际图并重算发现。逐目标选择性刷新可能更快，但需要额外证明影响闭包，超出本次个人实验边界。没有为了更多缓存命中而删除配置身份。

个人扩展选择条件 include 和宏开关，补足已有 `-O0` → `-O1` 测试只验证刷新而未改变边集的缺口。开启宏后 extra.h 进入实际图，撤销后消失；源码不变，因果只归于配置。两方向都比较同提交全量结果，并保留固定手写边集，避免仅用被测函数生成答案。

官方基础镜像按固定 digest，APT 与 PyPI 使用显式官方参数；个人镜像只复用本轮官方源构建出的依赖层，不沿用 E7 的第三方镜像层。实验容器禁网并绑定镜像 ID。个人测试在运行时未提交，所以保留当时真实的 dirty=true、文件快照与哈希；后续正式提交不回写这些运行元数据。

## 代价与覆盖范围

全局配置改变会多刷新未受影响的 helper.o，属于保守策略；支持范围内优先正确性。本轮未评价性能收益，不将 elapsed_s 单次值解释为加速比例。条件编译例子仅使用既定受支持宏配置，复杂命令、目录、系统头文件追踪和公共异步契约仍不在教学 MVP 范围内。

## 实际验证

个人镜像通过 48 项 BuildChecker 服务测试、16 项 EChecker 服务测试及 5 项编排测试，参考 E8/E9 与真实条件编译扩展均通过。启用宏新增一条 MISSING，撤销宏仅消除该条；源码哈希不变，增量 actual/declared/findings 与全量一致。`personal-final/mutation` 证明忽略 flags 的错误复用会被个人用例拒绝，正常镜像再跑两项个人测试通过。原始日志、失败与复跑说明见 [个人报告.md](个人报告.md)。

跨平台的候选 Dockerfile 哈希按 Git LF 原字节固定。首次完整回归因 Windows CRLF 产生一项失败，恢复原字节后重建最终镜像，103 项仓库回归通过；不为通过检查而改动既有溯源值或公共测试。个人测试与镜像内源码哈希一致，8 份历史 bundle 可独立恢复。
